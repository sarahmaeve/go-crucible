# Evidence Packet 4: Error output and source boundary

The local validator currently returns no error for the affected declarations.
The converter later fails without naming an editable Dockerfile instruction.
The release system can already keep a file, line, and instruction for every
stage-dependency record that the user wrote.

[BuildKit PR #999](https://github.com/moby/buildkit/pull/999) documents an
upstream Dockerfile-stage cycle that could make `dockerd` call the same
function until its goroutine ran out of stack space.
[BuildKit PR #4567](https://github.com/moby/buildkit/pull/4567) later added
source locations to the cycle error.

Those changes inspired the report and its requirement for a useful error. The
local stage names, counters, traces, API, and tests are invented. They do not
reproduce BuildKit's complete converter.
