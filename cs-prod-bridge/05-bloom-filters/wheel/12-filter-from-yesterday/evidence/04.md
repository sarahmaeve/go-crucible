# Evidence Packet 4: Production source and exercise boundary

The [Apache Cassandra storage-engine documentation](https://cassandra.apache.org/doc/latest/cassandra/architecture/storage-engine.html)
describes SSTables as immutable and lists a Bloom filter as one of an SSTable's
components. It also explains that compaction writes a new SSTable before the
old ones are removed. This supports the rule used by the exercise: a filter
must stay paired with the data whose keys it represents.

The source does not report this incident or describe the local `Catalog` API,
route names, generation numbers, measurements, or repair. Those details are
invented. The exercise illustrates a general mistake—pairing a filter with the
wrong data—and does not reproduce Cassandra's implementation.
