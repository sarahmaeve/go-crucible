# Evidence Packet 3: Heap and deletion behavior

The in-use heap profile attributes 71% of retained objects to cache keys and
metadata reachable from the resolver's map.

Instrumentation confirms that the resolver never calls `delete`. The cache is
replaced when metadata publication advances to a new snapshot, normally once
per deployment. Heap growth begins immediately after each replacement and
tracks observation rate.

This evidence does not evaluate how the runtime reuses buckets after deletion,
because no deletion occurs on the observed path.
