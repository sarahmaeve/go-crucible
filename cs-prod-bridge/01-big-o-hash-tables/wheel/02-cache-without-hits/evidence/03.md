# Evidence Packet 3: Memory and deletion behavior

The in-use heap profile shows that cache keys and metadata use 71% of the
objects still in memory. The resolver's map can reach all of these objects.

Measurements confirm that the resolver never calls `delete`. A metadata update
replaces the cache with a new snapshot, usually once per deployment. Heap growth
starts immediately after each replacement and follows the observation rate.

This evidence gives no information about how the runtime reuses buckets after a
deletion because this code path does not delete entries.
