# Evidence 04: API rules

The API review records these rules:

```text
ordering: newest incidents first
identity: each incident has one ID that does not change
pagination: every item in one fixed snapshot appears exactly once
page token: clients send it back unchanged; the server may change its encoding
updates: the service publishes a complete new snapshot between page sequences
```

The current cursor type already has fields for `OccurredAt` and `IncidentID`.
The endpoint populates and compares only `OccurredAt`.

Before you open the code, write which API rules need an exact order. Also write
where the endpoint must apply that order and what each cursor field can
identify.
