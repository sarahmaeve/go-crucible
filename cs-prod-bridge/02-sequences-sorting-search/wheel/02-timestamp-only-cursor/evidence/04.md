# Evidence 04: API Requirements

The API review records these requirements:

```text
ordering: newest incidents first
identity: incident ID is unique and immutable
pagination: every item in one immutable snapshot appears exactly once
page token: opaque to clients; server may change its encoding
mutation: snapshot updates are published atomically between traversals
```

The current cursor type already has fields for `OccurredAt` and `IncidentID`.
The endpoint populates and compares only `OccurredAt`.

Write the comparison as two steps: compare timestamps first, then compare IDs
when the timestamps match. Apply those steps to sorting, deciding whether an
incident follows a cursor, and filling in the next cursor.
